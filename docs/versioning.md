# LeanReuse 版本管理

当前工程版本写在仓库根目录的 `VERSION` 中。每个正式版本同时具备三项记录：

1. `VERSION` 中的版本号；
2. `CHANGELOG.md` 中的变更摘要；
3. 指向对应提交的带说明 Git 标签 `vX.Y.Z`。

标签一旦发布就不移动、不覆盖。日常开发继续在 `main` 上进行，因此任何后续改动都不会
改变已经保存的版本。

## 版本号规则

- 主版本号：架构、数据协议或公开入口发生不兼容变化；
- 次版本号：增加向后兼容的功能或实验能力；
- 修订号：修复问题、完善检查或更新文档，不改变主要使用方式。

## 查看和比较

```powershell
git show v1.0.0 --stat
git log v1.0.0..main --oneline
git diff v1.0.0..main
```

第一条查看第一版内容，后两条查看第一版之后新增的提交和文件差异。

## 安全还原

若要从第一版继续修改，推荐从标签建立一条新分支：

```powershell
git switch -c restore/v1.0.0 v1.0.0
```

这样不会删除当前开发记录。检查完毕后可回到主分支：

```powershell
git switch main
```

若只想临时查看第一版而不修改：

```powershell
git switch --detach v1.0.0
git switch main
```

不要用 `git reset --hard` 做常规还原；它可能清除尚未提交的修改。任何准备长期保留的状态，
都应先提交，再创建新的版本标签。

## 发布后续版本

后续版本按以下顺序建立：更新代码和文档，运行轻量自检，更新 `VERSION` 和
`CHANGELOG.md`，提交修改，最后创建并推送带说明标签。正式实验结果还必须记录运行模式、
规模和冻结引理库快照哈希，不能仅依赖版本号。
