# 阶段 29 执行日志（文字体系重构：固定双尺度、收紧唯一接口）

## 为什么做这一单元

外部评审指出，项目的主要问题不是“双尺度”方向本身，而是两条路径之间连接过多、
测量口径混杂，以及历史叙事把若干尚未证实的代理量写成了结论。用户已明确批准修改
“自博弈”“子模性保证”“reuse 因果价值”等原有表述，因此本阶段先统一全部活跃文档，
暂不改代码与实验数据。

## 本阶段固定下来的口径

1. 系统保留两个尺度：在线单题求解与离线引理库建设；二者只通过冻结的
   `LibrarySnapshot` 相连。
2. 在线路径只消费库，不写库；临时引理只属于当前目标。
3. 先按相关性召回，再在相关候选中使用 `reuse/cost` 排序，避免“高复用但不相关”。
4. `reuse` 只表示通过内核验收的证明中的跨目标使用证据，不再称为因果价值。
5. 新引理先进入 probation；只有得到跨目标使用证据后才能进入 active；长期无曝光者
   不得因“零复用”直接淘汰。
6. 严格 pass@k 只统计第一轮模型候选；廉价兜底与 repair 另列工程成功率。
7. C 在内部拆成 C-build 与 C-measure；D 只调试；T 在框架与库冻结后只跑一次。
8. 三组正式对照改为：A=真实需求+Guide，B=真实需求+reuse，C=伪需求+reuse；
   A/B 必须共享候选池，避免比较两个同时变化的因素。

## 反向对照

文档一致性检查使用同一组“禁用旧主张”规则：

* 对当前活跃文档运行，结果应通过；
* 将旧句“真实 pass@k 具有单调子模保证”直接送入同一检查，检查必须失败。

反向样例确实被拒绝，说明检查不是空转。该对照只验证文字口径，不宣称代码已经完成
目标态迁移。
