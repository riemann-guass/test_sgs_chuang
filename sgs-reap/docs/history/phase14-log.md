# 阶段 14 执行日志（P3：引理库 + 覆盖度 → 闸门 G3）

N2 的核心创新点是"引理库 = 工作负载驱动的子模最大化"。G3 要回答的是：
**cover 有没有便宜且仍具子模性的代理？** 有 → 可以用贪心 + (1−1/e) 近似界；
没有 → 放弃近似保证，N2 改述为启发式选择。

## 两个 cover 的分工（这是本阶段的关键设计）

| | 怎么判"这条引理对 w 有用" | 代价 |
|---|---|---|
| **`sig_cover`（代理）** | 引理语句的签名出现在 w 的**证明轨迹**里（签名来自已落盘的 `trace` 数据） | **0 次 Lean 调用** |
| `dependency_cover`（可信版） | w 的证明**真的引用**了这条引理（依赖抽取） | 每个目标一次 Lean 调用 |

两者都是"并集覆盖"形式，因此**天然单调子模**；代理之所以便宜，是因为它复用 P2 已经落盘的轨迹，
不需要为每次评估再跑 Lean。G3 就是来验这一点。

判定准则（跑前定死）：**0 子模性违例 且 贪心 ≥ (1−1/e)·OPT**。

## 闸门 G3：**通过**

* **代理确实便宜**：`sig_cover` 需要 **0 次 Lean 调用**（只读轨迹），可信版 `dependency_cover`
  要对每个目标跑一次（本语料 35 次）；
* **子模性经验检查 0 违例**（500 次随机 A ⊆ B 的边际增益递减检查）；
* **贪心达到最优**（小实例上比 1.000 ≥ 0.632 的 (1−1/e) 界）。

所以 N2 可以用"贪心选 top-B 引理入库"，并保留 (1−1/e) 的近似说明。

### 必须写清楚的两条限制

1. **子模性在这里有一部分是"构造保证"**：`sig_cover` 是并集覆盖函数，数学上必然子模；
   这次经验检查的作用是**防实现 bug**（比如重复计数），不是"证明了新性质"。报告里如实标注。
2. **代理的"忠faithfulness"没被检验**：`sig_cover` 把"签名出现在轨迹里"当成"引理有用"，
   但这个近似的**偏差**要用 `dependency_cover`（真依赖）当基准才能量出来——那需要一个
   真库 + 真候选池（P3 收尾 / P4 的对照），本轮语料只有 35 个目标、39 条签名，
   覆盖数只有 3，统计意义不足。

同时这也再次印证 phase9 的结论：**要让 N2/N3 有区分度，工作负载必须是同族引理**
（共享中间事实链），否则覆盖度天然稀疏、贪心几乎选不出有意义的组合。
