# SG-Lean 思路框架（v2，含实测修正）

> `docs/proposal.md` 是立项时的方案（v1）。本文件是**跑过 A→D 之后**的框架：
> 保留 v1 的骨架，但把实测推翻或收窄的假设逐条改写。凡标注「实测」的，都有 `experiments/results/` 里的数据与对应 `phase*-log.md`。

## 一、一句话

把 SGS 的三角色自博弈搬到**推理期**：用**形式化测量**替换 LLM 评判，用**引理库**替换权重更新。

## 二、从 SGS 推到 SG-Lean 的三步

SGS 的贡献拆开是三条，不是一条：

1. **条件化在未解目标上生成**（不是随机出题）；
2. **出题的价值由"实测结果"决定**（`solve_rate` 实测 + review 相乘）；
3. **用这个价值更新 Conjecturer 的权重**——这是它"越练越强"的来源。

推理期的 tactic 形态承载不了第 3 条（没有跨 episode 的权重更新）。于是：

- **载体替换**：既然"变强"不能靠权重，就靠**工件累积**——引理库 + 提示词记忆注入；
- **判据替换**：SGS 的 Guide 是**训练期**的产物（判"合成题对学习有多大价值"），
  而推理期需要的是"这条引理对**当前这个目标**有多大即时效用"。实测两者差距很大
  （Guide 的分数与候选可用性几乎不相关，且占一次标定的 98% completion token）。
  所以判据换成 **Lean 能直接算出来的量**：不需要猜，也不需要花 token。

## 三、框架主体：三层 + 一个载体

```
┌─ 生成层（谁提出候选） ────────────────────────────────────────────┐
│  Solver      : 整篇证明（对引理） / 搜索（对主目标）                │
│  Conjecturer : 候选引理，条件化在 [未解目标 + 需求签名 + 库范例]     │
└──────────────────────────────┬───────────────────────────────────┘
                               ▼
┌─ 判据层 G（候选值不值得留） ──────────────────────────────────────┐
│  ① 门检   : 是不是合法命题（elaborate 成 Prop）        ← 免费       │
│  ② 硬门   : 非平凡 ∧ 新颖 ∧ 可证                       ← 便宜       │
│  ③ 软分   : 压缩收益 / 覆盖收益                        ← 需证明文本 │
└──────────────────────────────┬───────────────────────────────────┘
                               ▼
┌─ 选择层 N2（有限库容留给谁） ─────────────────────────────────────┐
│  cover(S) = 工作负载 W 上的净收益（有库 vs 无库）                   │
│  在候选池上做贪心/子模最大化                                        │
└──────────────────────────────┬───────────────────────────────────┘
                               ▼
┌─ 载体（替代权重） ────────────────────────────────────────────────┐
│  引理库（物化成有名常量，真正能被 import） + 提示词记忆注入          │
└──────────────────────────────────────────────────────────────────┘
```

## 四、关键定义（当前这一版）

```
需求强度    d(g) = freq(g) × cost(g)
            freq 分层统计：成功轨迹 / 失败轨迹；跨 ≥m 个目标才升级为"需求"

硬门        非平凡：simp/aesop/decide 在预算内解不出
            新颖  ：不与**父目标**、也不与库中等价（α + δ 等价）
            可证  ：solve_rate > 0

cover(S)    评分制，不是 0/1 翻转：
            cover(S) = Σ_{w ∈ W} [ rate_with(S, w) − rate_without(S, w) ]
            rate = 通过数 / k（只生成出 n<k 篇时，空缺仍记为失败）

W（工作负载）必须含**近失手**目标（0 < solve_rate < 1）——
            这是 cover 唯一有信号的地方；用"最难的题"会得到两臂皆 0 的无信息结果。
```

## 五、实测推翻/收窄的假设（框架必须反映的部分）

| v1 的假设 | 实测结果 | 框架修正 |
|---|---|---|
| 把需求签名列进提示词就能引导出题 | 第一版模型把需求**原样抄回**当候选（15/15 全是抄的），而目标是另一类题 | 需求只能作为**背景证据**，并加"引理必须提到目标里的符号"的硬约束 |
| 过门检 = 可用 | 重言式（`X → X = X`）与无关命题都能过门检 | 必须补**相关度**与**硬门**；"过门检"单独看是可被刷满的指标 |
| 最难的题是好的测量集 | `targets_hard` 上两臂**皆 0**（该集合的定义就是"Solver 最不擅长的") | W 必须按难度分档，用近失手集合 |
| 库是"变强的载体"，越大越好 | 库只有 4 条、只覆盖 2–3 个目标 → 增益必然测不出 | **先扩库再谈增益**；覆盖不到的目标不该指望被帮到 |
| 判定预算是次要工程问题 | 预算伪影造出过**两个假结论**：G1 的"非零解 13.3%"（实为 31.6%）、D v2 的"给库后 -3.75"（实为工具崩溃） | 工具层必须**显式自检**：环境预检 + 反向对照 + 判定可复现性检查 |
| 库只要"存在"就算可用 | `lake build SgsLean` 不编 `SgsLean.GeneratedLibrary`，处理臂环境里其实没有库 | "库可用"是**可验证的必要条件**，每次实验前先验 |

## 八、下一步的优先级（框架级）

1. **扩库**：跑完整流水线把库从 4 条扩到 15–30 条。覆盖不到的目标不该指望被帮到，
   而现在库只覆盖 2–3 个目标——这是"增益 0"最可能的解释。
2. **提高测量功效**：`--select mixed`（近失手 + 稳定可解）+ `k=6~8` + 重复 2–3 次，
   报**置信区间**而不是单点。
3. **看引用率**：处理臂里有多少证明真的写了 `sgs_lem_*`。若接近 0，
   问题在"提示词没让模型用库"，而不在"库没用"——那是可以先解决的工程问题。
4. **闭环（H1/H2 的前提）**：多轮 = 采集 → 需求 → 猜想 → 硬门 → 求解 → 入库 → 注入 → 下一轮，
   在**固定 held-out** 上测 pass@k，并与 `/guide`（LLM 评判）基线对照。

## 九、边界（明确不做）

* **不做梯度训练**——"变强"的载体是库，不是权重；
* **不碰搜索内 value**（那是 Bourbaki 的地盘）：我们的形式化信号用在**课程/选择层**；
* **不与"让出题器更聪明"这条轴正面竞争**（STP / SGS / LeanAgent 已占）。
