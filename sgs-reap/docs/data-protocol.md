# 数据使用规则

本文规定每份数据可以做什么。代码名称保留是为了字段稳定，正文同时给出通俗名称。

## 1. 固定划分

| 通俗名称 | 代码名称 | 文件 | 数量 | 允许用途 | 禁止用途 |
|---|---|---|---:|---|---|
| 建库集 | C-build | `data/minif2f_c_build.jsonl` | 122 | 需求、候选、候选证明 | 正式复用计数 |
| 复用测量集 | C-measure | `data/minif2f_c_measure.jsonl` | 61 | 试用、复用计数、晋升 | 产生候选 |
| 开发集 | D | `data/minif2f_dev.jsonl` | 61 | 调参、排错、配对比较 | 建库 |
| 最终测试集 | T | `data/minif2f_test.jsonl` | 244 | 冻结后一次性评测 | 调参、试跑、建库 |

三个 valid 分区来自同一份 244 题源文件，由固定种子和哈希排序精确切分。算法、数量和文件
哈希记录在 `data/dataset_manifest.json`。test 与 valid 的题目编号和规范化命题重叠均为 0。

## 2. 正式复用记录

一条引理的复用次数，是复用测量集中实际引用它的不同题目数。一次引用必须满足：

1. 当前题属于复用测量集；
2. 当前证明已经通过 Lean 验证；
3. Lean 证明项的常量集合包含该引理；
4. 当前题不是该引理的来源题；
5. 系统确实向当前题展示过该引理。

失败证明、证明文本中的名字、同一题重复引用、开发集或最终测试集上的引用都不计数。

## 3. 建库流程

```text
建库集产生候选
→ 候选通过硬性检查并进入待观察状态
→ 复用测量集提供独立试用机会
→ 根据通过证明中的实际引用晋升为已发布引理
→ 只物化并冻结已发布引理
```

建库集可以用于调试候选是否可能被引用，但不能作为正式晋升证据。

## 4. 开发和最终测试

开发集可以反复运行，用于确定参数和发现工程故障，但不能产生或更新引理。最终测试集在代码、
参数、模型配置、提示词和引理库全部冻结后运行一次。第一次查看最终测试结果后，不得再根据它
修改系统并重新把结果称为留出测试。

`evaluate.py` 为最终测试维护运行台账；建库入口还会按路径、内容指纹和行内角色三层检查数据。

## 5. 来源字段

建库集和复用测量集使用 `source_corpus=MF_VALID_C`，开发集使用
`source_corpus=MF_VALID_D`。只有 `MF_VALID_C` 允许出现在引理来源中。

旧 C1/C2、Mathlib 抽样课程集和相应实验已经退役，只存在于 Git 历史和阶段日志中。
